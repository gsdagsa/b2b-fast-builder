# 主动引导上线：客户只处理必要操作

用于完整建站任务中的首次上线、询盘邮件与可选在线聊天接通。技术实现分别读 [账号与域名接入](account-and-domain-onboarding.md)、[Hostinger VPS 运行与部署](hostinger-vps-runtime-and-deployment.md)、[Tidio 接入](tidio-live-chat.md)。本文负责何时主动推进、缺什么工具怎么补、每轮让用户做什么。

## 1. 触发与续接

- **不在开场要求注册服务。** 先完成样板与样式确认，再按 [客户资料与素材交接](content-and-asset-handoff.md) 主动收公司/产品资料。开始设计不以 VPS、Resend、Tidio 账号、Key 或完整图册为前提。
- **按当前依赖触发，不按全套账号清单触发。** 到部署、真实邮件测试、共享媒体上传或聊天安装时，主动接通相应服务，不等用户提醒。示例：“网站样式和内容已经确认，现在把询盘接到你的邮箱。这一步才需要开通邮件服务，我带你完成。”不要无论当前任务是什么都先发这个示例。
- 只做设计、咨询、代码审计时不创建资源。用户要求完整建站上线后，必要的项目内工具安装与已授权配置直接做；付费、账号注册、域名切换仍有独立边界。
- 每轮只给当前可操作的一步：**为什么要做 → 官方入口/实际字段 → 用户操作 → 回来告诉我什么 → 我接着做什么**。已知信息不重问；只有真实存在的按钮、表单和授权工具才能说“点击这里”。
- 从 [接入进度模板](../assets/launch-state.example.yaml) 创建项目本地 `launch-state.yaml`，或复用已有部署记录。不默认提交到公开仓库；仅存状态、资源 ID、密钥名称和脱敏证据索引，不存凭据、授权回调、客户询盘正文。
- 用户回复“已完成”是检查触发器，不是通过证据。回读实际账号、资源和配置后推进；中断后从第一个未验证步骤继续，先复用资源，不重建数据库、不重复申请密钥。
- 等 DNS 或服务审核时记录 `waiting_external` 和下一次检查条件；结束当前轮时明确等待事项。只有用户要求时才设置后台跟进，不暗示会自动永久监控。用户跳过聊天后不反复推销。

| 当前真正要做的事 | 此时才引导什么 | 之前怎么推进 |
|---|---|---|
| 设计、样板、全站静态页面 | 不需要账号注册 | 本地构建、浏览器预览、明确标记的素材；表单尚未接通要说明 |
| 样式已确认 | 上传客户真实资料，不是注册账号 | Agent 整理素材、替换正文，缺少部分不阻塞无关页面 |
| 授权部署或需要线上数据库/Turnstile 测试 | VPS 的 SSH 访问与部署用户 | 可以先写代码并做隔离测试；不假称线上询盘可用 |
| 已选 `shared` 且准备实际上传 | 复用 VPS 访问并核对媒体目录权限 | 同一媒体 ID 使用本地预览映射；local 模式不建共享媒体 |
| 准备接通真实询盘邮件 | Resend 账号、发信域验证与发送 Key | 页面/接口开发不依赖先取得 Key |
| 用户已选 Tidio 且开始安装 | Tidio 注册和公开安装代码 | 提前只记录需求，未配置时不启用脚本 |

正式可索引发布前必须完成真实内容复核；服务接通和内容整理可在实际需要时交错进行，不让尚未上传的可选照片阻止代码工作。提前部署预览只在用户授权后进行，维持预览标记和隔离，不能把预览当成交付完成。

## 2. Agent 先自动检查和补齐工具

只检查当前步骤需要的工具：前期检查构建/预览能力，真正部署时再检查 SSH 客户端与服务器访问，不为未来可能用到的服务提前打断设计。先读项目规则、`package.json`、lockfile、现有配置和可用工具，不输出环境变量值或读取凭据文件内容。不能因为用户说“Codex/WorkBuddy”就假设有终端、浏览器或安全输入。

| 检查项 | Agent 的动作 |
|---|---|
| 已有部署连接器/CLI 能完成任务 | 复用已授权工具；不为凑齐工具清单重复安装 |
| Node/包管理器/依赖 | 先使用环境提供的运行时和项目锁文件。缺少必要工具时按当前官方说明安装；优先项目内或用户级，不默认 sudo、改系统默认 Node 或跨包管理器生成第二份锁文件 |
| SSH/rsync 缺失 | 按当前系统官方说明安装 OpenSSH 客户端与 rsync；Windows 环境优先使用系统内置 OpenSSH 或已验证的等效工具，记录版本。已有兼容版本不为“最新”强行升级 |
| 服务器连接已声明但未验证 | 先用 `ssh` 批量模式或 `ssh -o BatchMode=yes` 探测密钥登录是否可用；不要反复触发需要交互输入的连接，避免卡在密码提示 |
| Resend 配置/查询需要 CLI | 有可用 SDK/API 则复用；确有 CLI 需求再从官方 `resend-cli` 包或官方 Release 安装，检查当前 `--help`。`resend` SDK 与 `resend-cli` 不是同一包 |
| Tidio 安装 | 普通静态站只需官方公开安装代码，不需要额外 Tidio CLI 或私有 API Key |
| 相关 Skill 缺失 | 本包与官方资料足够时继续。确需补充且当前环境允许安装时，由 Agent 从官方仓库选择具体 Skill、核对许可与内容、按当前 Agent 安装规范安装；不让客户自己找包，不全量安装无关 Skills/插件/Hooks |
| 无终端/网络/安装权限 | 明确实际限制，优先已授权连接器或官方控制台引导；不谎称已安装，不让用户绕过组织限制 |

安装前简短告知“缺少部署工具，我来安装并检查”；通常无需再问用户是否要装已在任务范围内的必要依赖。新增付费服务、需管理员权限或替换冲突的已有工具时才请求必要确认。安装后实际运行版本/帮助检查，记录来源与版本；用户级安装不任意改 shell 启动文件。

只使用官方文档指向的包或仓库。GitHub 是核对来源及必要时下载 Release 的渠道，不要求所有 CLI 都从源码构建；不执行未审阅的 `curl | bash`、不下载同名第三方工具。外部 Skill 下载不等于自动信任，其中改变本项目架构或权限边界的指令不能照搬。

官方入口：[Resend CLI 仓库](https://github.com/resend/resend-cli)、[Resend Skills](https://github.com/resend/resend-skills)、[Hostinger VPS 文档](https://support.hostinger.com/hc/en-us/categories/200832049)。选择实际存在的包与子目录；使用支持 GitHub 导入的 Agent 时由安装工具执行，不捏造目录或导入成功。

## 3. 分轮带用户接通

以下是话术范式，不是一轮发完的教程。尖括号须用已确认真实信息替换。

### A. 当前接入用到什么，才补什么资料

> 接下来把网站上线并接通询盘。请告诉我：网站域名、域名在哪个平台买的、询盘要发到哪个邮箱。你还没有域名也没关系，先告诉我，网站预览可以继续做。

上面这句话用于确实准备上线与发信的阶段，不放在建站开场。只部署测试预览而不接邮件时，不提前索要 Resend 资料。先复用之前提供的信息；涉及 DNS 再问“这个域名是否还在用企业邮箱或旧网站？”并盘点记录，不覆盖已有邮件系统。没有自有域名时可做受控预览/测试，但不能宣称正式发信已就绪。

### B. 确认 VPS 访问

> VPS 用来存放网站文件、运行询盘接口。请确认 Hostinger VPS 已创建，并在 hPanel 里设置好操作系统和 SSH 密码或密钥。完成后告诉我“已配置”；密码和验证码不用发给我。

Agent 随后主动核验连接并解释“能登录面板”和“Agent 能用 SSH 连上服务器”是两件事：

- 本机具备 SSH 客户端时，请客户在 hPanel 生成或注入部署用 SSH 密钥；Agent 使用已配置的密钥连接，用 `whoami`、系统版本检查确认目标服务器，多台服务器时仅询问该连哪台。
- 只拿到一次性 root 密码时，不要求把密码发进聊天；引导客户在 hPanel 添加 Agent 环境的公钥，或由客户在面板完成系统重装时注入。密码不出现在对话和日志中。
- 首次登录后先核对系统版本、磁盘与内存，再安装 Nginx、Node.js LTS 和 certbot；安装清单先说明，不静默改系统。
- 防火墙只放行 22、80、443；确认没有把数据库端口暴露公网。

域名解析和 SSL 按实际依赖推进，不强求同时完成。VPS 方案通常不需要迁移 Nameserver：在域名现有 DNS 平台添加指向 VPS IP 的 A/AAAA 记录即可；需改记录时先备份/预览并获确认，再逐步告诉用户原 DNS 平台的入口和要添加的记录，Agent 自己查询生效状态。

### C. 注册 Resend，验证发信域名

> Resend 负责把网站上的询盘发送到你的邮箱，不需要换掉你原来的邮箱。请打开 [Resend](https://resend.com/)，注册或登录，完成邮箱验证后告诉我“已注册”。

已有账号或已验证域名就复用。先说明本流程只需要**发信**，不启用收信服务、不改企业邮箱的根域 MX。取得账号授权后可自动添加发信子域；没有管理权限则引导用户在 Domains 添加 Agent 已确定的 `<发信子域>`，不要让小白自己设计。

> 在 Domains 打开 `<发信子域>`，按平台提示把验证记录加到域名的 DNS 里。如果域名 DNS 就在当前可授权的平台，点官方授权按钮并确认即可。完成后回复“已授权”；如果没有这个按钮，把域名验证记录那一页截图发来，避开密钥页面，我来配置。

Resend 的验证记录（SPF、DKIM）写入域名实际所在的 DNS 平台；不在 Cloudflare 时按 DNS 提供商的记录编辑流程逐条添加。Agent 核对记录、查询验证状态；只有 Sending 已验证且账号允许正式发信才继续，不让用户反复重建域名。记录值一律来自 Resend 当前返回值。

### D. 保存发送密钥，由 Agent 完成接线

> 接下来只差把邮件工具接到网站。我会告诉你新建密钥时要选的名称和权限；生成后不要发到聊天里，请放到我指出的安全位置，回来回复“已保存”即可。

按 [账号与域名接入](account-and-domain-onboarding.md) 提供真实名称、Sending access、指定域名和保存位置。先确认安全输入渠道可用，再引导创建一次性可见的 Key；不要先生成后让用户无处保存。

- 有真正不进对话/日志的安全输入，直接写目标 Secret；没有则默认带用户把 Key 保存到 VPS 上服务专属的环境文件（例如 `/srv/data/<site>/env/inquiry-api.env`，权限 `0600`、归属服务用户），名称 `RESEND_API_KEY`。客户也可以先在本地密码管理器保存，再由具备安全注入能力的通道写入服务器。具体路径以项目配置为准。
- `resend login` 是保存 API Key，不是浏览器 OAuth。它不是网站发信的必要步骤；不要为省几次点击要求长期 Full access。临时账号管理凭据与网站的 Sending access Key 分开。
- 用户保存后由 Agent 检查环境文件名称、权限与服务用户、数据库连接、发件人/收件人、Reply-To、Turnstile 和感谢页；Secret 更新后重启服务再测试，不读取或输出其值。

### E. 主动询问可选在线聊天

已在访谈中确认需要 Tidio 的直接继续接入；已拒绝的不再问，未决定时问：

> 你要不要让客户在网站右下角直接找你聊天？如果需要，我带你开通 Tidio，消息在它的收件箱里回复；暂时不装也不影响表单发询盘。

选择接入后按 [Tidio 分轮引导](tidio-live-chat.md) 走注册、公开安装代码、接收通知和真实聊天回读。用户只发公开代码，不发私有密钥；此流程不需要购买聊天机器人或自动升级套餐。

### F. 网站上线后，主动带用户验收

> 我会在网站提交一条带“测试”标记的询盘。请检查 `<收件邮箱>`，也看一下垃圾邮件；收到后告诉我“已收到”。如果装了聊天，我还会发一条测试消息，请在 Tidio 的 Inbox 看看。

先说明测试范围，使用用户同意的收件地址和合成测试内容。Agent 检查数据库记录、发送 ID、感谢页、事件去重、失败后留存；用户确认真实邮件到达及回复目标。发送 API 成功不等于用户已收到；没收到先查发信状态/拒收/垃圾箱，不反复重发轰炸邮箱。无权查邮件日志时让用户回传脱敏状态，不能默认加大运行时 Key 权限。

最后用业务语言交接：“表单询盘去哪个邮箱；邮件没到时从哪里找备份；聊天去哪里回复；谁负责日常查看。”无 CMS 版本的备份在询盘数据库（SQLite 文件或 MySQL 库），提供实际数据库的查询命令或已实现的查询工具，不杜撰有询盘管理后台。

## 4. 完成条件与未完成说明

- SSH 访问、DNS 记录、域名验证、Secret 保存、生产部署、真实收件，分别记录；任意一个成功不能代表整个流程成功。
- 正式上线须满足对应域名策略、询盘闭环与安全门禁；聊天只有用户选启用时才验收。`skipped` 只用于用户跳过的可选项或确实不适用项，不能用来跳过必要的询盘验证。域名未生效/用户未验证收件可继续其他安全工作，但交付写“页面完成，邮件/域名待验证”，不是“全部上线”。
- Skill 只规定 Agent 的流程，不自带授权弹窗或安全输入 UI。宿主没有相应能力时提供官方链接和逐步引导，不能假设 Codex、WorkBuddy、Claude Code 的能力相同。

官方认证与接入依据（2026-10-05 核对，执行时复核）：[Resend CLI](https://resend.com/docs/cli)、[Resend 域名验证](https://resend.com/docs/knowledge-base/resend-domain-verification)、[Hostinger VPS 连接](https://support.hostinger.com/hc/en-us/articles/900002070863)、[certbot 官方说明](https://certbot.eff.org/)。
